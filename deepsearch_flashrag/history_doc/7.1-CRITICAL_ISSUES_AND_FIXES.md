# 关键问题分析与修复方案

## 当前问题诊断

从 `intermediate_data.json` 分析，发现了以下**严重问题**：

### 问题1：模型输出格式混乱 ⚠️

**现象**：
- 有些样本正确输出了 "So the answer is: Francisco Bru"
- 但有些样本（如dev_3）输出了大量重复文本：`"limburg limburg limburg..."`
- 有些样本的 `pred` 包含了整个思考过程，而不是只提取答案

**原因**：
1. 答案提取器被注释掉了（`use_answer_extractor: False`）
2. 模型在某些情况下陷入了循环生成
3. Prompt可能不够强制要求格式

### 问题2：答案提取失败 ⚠️

**现象**：
- `pred` 和 `raw_pred` 相同，说明没有进行答案提取
- 当 `raw_pred` 包含大量无关文本时，`pred` 也会包含

**原因**：
- 配置文件中答案提取器被注释掉了

### 问题3：检索质量不足 ⚠️

**现象**：
- dev_0的答案 "Francisco Bru" 是错误的，正确答案是 "Kai Tomety"
- 检索到的文档虽然相关（Peru national football team），但可能不包含正确答案

**原因**：
- 检索到的文档可能不完整
- 需要更多相关文档才能找到正确答案

### 问题4：IRCoT迭代失效 ⚠️

**现象**：
- 有些样本在迭代过程中出现大量重复文本
- 迭代没有有效推进推理

**原因**：
- 模型可能陷入了循环
- 需要更好的停止条件或prompt约束

---

## 紧急修复方案

### 修复1：启用答案提取器（最重要！）

**立即修改配置文件**：

```yaml
# 答案提取配置 - 必须启用！
use_answer_extractor: True
answer_extractor_method: "regex_and_keyword"
answer_pattern: '[A-Za-z][A-Za-z0-9\-_\s.,;:()]+'  # 更宽松的匹配模式
```

### 修复2：改进Prompt，强制格式

**问题**：当前prompt可能不够强制，导致模型不按格式输出

**解决方案**：使用更严格的prompt模板，在每次迭代都强调格式要求

### 修复3：增加检索数量和质量

**当前**：`retrieval_topk: 30`, `rerank_topk: 12`

**建议**：
```yaml
retrieval_topk: 50  # 进一步增加
rerank_topk: 20    # 保留更多文档
```

### 修复4：限制生成长度，防止循环

**当前**：`max_tokens: 512`

**建议**：
```yaml
generation_params:
  max_tokens: 256  # 减少，防止生成过长文本
  temperature: 0.0  # 确保确定性
```

### 修复5：改进IRCoT停止条件

**问题**：模型可能陷入循环，需要更好的停止机制

**建议**：检查生成的思考是否重复，如果重复则提前停止

## 根本性问题分析

### 为什么效果这么差？

1. **答案提取器被禁用**：这是最严重的问题，导致答案格式混乱
2. **模型输出不稳定**：有些样本正常，有些样本陷入循环
3. **检索召回不足**：可能正确答案不在检索到的文档中
4. **IRCoT迭代无效**：多轮迭代没有有效推进推理

### 预期改进

实施这些修复后，预期：
- **EM**: 从 0.0 提升到 0.05-0.15（至少有一些样本能正确提取）
- **F1**: 从 0.061 提升到 0.15-0.30（答案提取后会有明显提升）

## 长期改进方向

如果修复后效果仍不理想，考虑：

1. **更换生成模型**：Qwen2.5-14B可能不适合这个任务，考虑使用更大的模型
2. **改进检索策略**：使用混合检索（hybrid），结合多个检索器
3. **优化Prompt**：根据实际输出调整prompt，使其更符合模型的行为
4. **后处理**：对提取的答案进行清理和标准化
5. **使用不同的Pipeline**：如果IRCoT不适合，考虑使用Sequential或Adaptive pipeline
