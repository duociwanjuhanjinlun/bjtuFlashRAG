# 检索优化检查清单

## 1. E5 模型的 query 前缀 ✅

### 问题描述
E5 模型（如 e5-base-v2）在训练时使用了非对称指令：
- **查询侧 (User Query)**：必须加前缀 `"query: "`
- **文档侧 (Database)**：通常需要 `"passage: "`（在构建索引时已添加）

如果不加前缀，E5 的性能会下降 **20% 以上**。

### 检查结果
✅ **已正确处理**：
- FlashRAG 的 `parse_query` 函数会自动为 E5 模型添加 `"query: "` 前缀
- 代码逻辑：`flashrag/retriever/utils.py` 中的 `set_default_instruction` 函数会检测模型名，如果是 E5 模型，自动设置 `instruction = "query: "`
- 配置文件已显式设置 `instruction: "query: "` 以确保正确性

### 验证方法
运行时会看到日志：
```
Use `query: ` as retreival instruction
```

## 2. 混合检索的权重 (RRF) ✅

### 问题描述
BM25 擅长精确匹配（专有名词），E5 擅长语义匹配。
- BM25 分数范围：0-infinity
- E5 余弦相似度：0-1

如果直接相加分数，会导致量级不匹配。

### 解决方案
✅ **使用 RRF (Reciprocal Rank Fusion)**：
- RRF 基于排名而非分数，避免了量级不匹配问题
- 公式：`RRF_score = Σ(1 / (k + rank))`，其中 k 是超参数

### 配置优化
对于 Wiki18 这种包含大量专有名词的数据集：
- **当前配置**：`rrf_k: 40`
- **推荐范围**：20-60
  - k 值越小 → BM25 权重越高（适合专有名词多的数据集）
  - k 值越大 → E5 权重越高（适合语义匹配多的数据集）

### 调整建议
- 如果发现 BM25 检索到的文档质量更好，可以降低 k 值（如 20-30）
- 如果发现 E5 检索到的文档质量更好，可以增加 k 值（如 50-60）
- 可以通过对比实验找到最优 k 值

## 3. Refiner 配置说明

### 当前配置
- **Refiner 类型**：Selective Context（基于自信息压缩）
- **压缩率**：`reduce_ratio: 0.2`（移除 20% 的低信息量内容）
- **压缩级别**：`phrase`（短语级别）

### 注意事项
1. **Refiner 是在检索后对文档进行压缩**，不会影响查询
2. **可能的问题**：如果关键实体被压缩掉，会导致答案提取失败
3. **调试建议**：
   - 如果发现答案提取失败，可以暂时关闭 Refiner（`use_refiner: False`）
   - 或者降低 `reduce_ratio`（如 0.1）以保留更多信息

### 检查方法
查看 `intermediate_data.json` 中的检索结果，确认关键实体是否被保留。
