# 查询优化功能说明

## 概述

查询优化功能旨在提升 R1 Search Pipeline 的检索质量。通过实体识别、查询重写和多查询策略，帮助模型生成更精确、更有效的检索查询。

## 功能特性

### 1. 实体识别增强

- **规则基础识别**: 使用正则表达式识别人名、地名、组织名等实体
- **NER 模型支持**（可选）: 如果安装了 spaCy，可以使用 `en_core_web_sm` 模型进行更准确的实体识别
- **时间信息提取**: 自动识别年份、年代等时间信息
- **关系关键词提取**: 识别问题中的关系词（如 "coach", "director", "founded" 等）

### 2. 查询重写/扩展

- **同义词扩展**: 自动添加查询关键词的同义词（如 "coach" → "manager", "trainer"）
- **问题类型检测**: 根据问题类型（人物、地点、时间、组织、作品）调整查询策略
- **关键词优化**: 去除停用词，保留核心关键词

### 3. 多查询策略

- **查询变体生成**: 为复杂问题生成多个查询变体
  - 实体查询：只使用关键实体
  - 时间+实体查询：结合时间信息和实体
  - 关系+实体查询：结合关系词和实体
  - 简化查询：只保留核心关键词
- **结果合并**: 自动合并来自多个查询的检索结果，并去重

## 配置说明

在 `r1_search_v1.yaml` 中配置：

```yaml
query_improver_config:
  enabled: True          # 是否启用查询改进（默认 True）
  use_ner: False         # 是否使用 NER 模型（默认 False，需要额外安装）
  multi_query: False     # 是否使用多查询策略（默认 False）
  multi_query_num: 2     # 多查询策略时生成的查询数量（默认 2）
```

### 配置选项说明

- **enabled**: 主开关，控制是否启用查询改进功能
- **use_ner**: 是否使用 spaCy NER 模型。如果设置为 `True`，需要：
  ```bash
  pip install spacy
  python -m spacy download en_core_web_sm
  ```
- **multi_query**: 是否启用多查询策略。启用后，系统会为每个问题生成多个查询变体，并行检索后合并结果
- **multi_query_num**: 多查询策略时生成的查询数量（建议 2-3 个）

## 使用示例

### 示例 1: 单查询改进

**原始查询**:
```
"individuals with same name announced retirement early 2020s personal setback 1990s"
```

**改进后查询**:
```
"Kevin Anderson retirement early 2020s personal setback 1990s"
```

改进点：
- 提取了关键实体 "Kevin Anderson"
- 保留了时间信息
- 保留了关系关键词

### 示例 2: 多查询策略

**原始查询**:
```
"James Clement announced retirement early 2020s"
```

**生成的查询变体**:
1. `"James Clement retirement early 2020s"` (主查询)
2. `"James Clement early 2020s"` (实体+时间)
3. `"James Clement"` (纯实体)

所有查询的结果会被合并并去重。

## 性能影响

### 优点
- **检索质量提升**: 通过更精确的查询，提高检索到相关文档的概率
- **答案准确率提升**: 更好的检索结果带来更准确的答案

### 开销
- **计算开销**: 查询改进需要额外的处理时间（通常 < 100ms）
- **检索开销**: 多查询策略会增加检索次数（但结果会被合并）

## 最佳实践

1. **单查询 vs 多查询**:
   - 简单问题：使用单查询改进（`multi_query: False`）
   - 复杂问题：使用多查询策略（`multi_query: True`）

2. **NER 模型使用**:
   - 如果系统资源充足，可以启用 NER 模型获得更准确的实体识别
   - 对于大多数情况，规则基础的实体识别已经足够

3. **查询数量**:
   - `multi_query_num: 2` 通常是最佳平衡点
   - 过多查询（>3）可能带来性能开销，但收益有限

## 故障排除

### 问题 1: 查询改进失败

**现象**: 日志中出现 "Query improvement failed"

**解决**: 
- 检查 `query_improver_config` 配置是否正确
- 如果使用 NER，确保 spaCy 和模型已正确安装

### 问题 2: 多查询结果重复

**现象**: 检索结果中有大量重复文档

**解决**: 
- 系统已自动去重，如果仍有重复，可能是文档 ID 不一致
- 检查检索配置中的去重逻辑

### 问题 3: 查询改进效果不明显

**现象**: 改进后的查询与原始查询差异不大

**解决**:
- 检查问题中是否包含足够的实体信息
- 考虑启用 NER 模型以获得更准确的实体识别
- 尝试启用多查询策略

## 技术细节

### 实体识别算法

1. **规则基础**:
   - 大写开头的词（可能是人名、地名）
   - 引号中的内容（可能是作品名）
   - 特定模式（如 "the + 大写" 可能是组织名）

2. **NER 模型**（如果启用）:
   - 使用 spaCy 的 `en_core_web_sm` 模型
   - 识别 PERSON, ORG, GPE, WORK_OF_ART, EVENT 等实体类型

### 查询构建策略

1. **优先级**: 问题中的信息 > 思考过程中的信息 > 原始查询
2. **组合规则**: 实体（最多3个） + 关系（最多2个） + 时间信息
3. **扩展规则**: 添加同义词，去除停用词

### 多查询生成

1. **主查询**: 完整优化的查询
2. **实体查询**: 只使用关键实体
3. **时间+实体查询**: 结合时间信息和实体
4. **关系+实体查询**: 结合关系词和实体
5. **简化查询**: 只保留核心关键词

## 未来改进方向

1. **学习式查询扩展**: 基于检索结果反馈调整查询
2. **查询重排序**: 根据问题类型动态调整查询策略
3. **跨语言支持**: 支持中文等语言的实体识别
4. **查询缓存**: 缓存常见查询的改进结果
